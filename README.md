# 生死转盘 · Roulette Online

**局域网多人联机回合制游戏** —— Node.js 零依赖服务端 + 手写 WebSocket + UDP 局域网发现 + Android 原生壳

`Node.js ≥ 18` · `零第三方运行时依赖` · `Windows exe / Android APK / PWA 三端交付`

</div>

---

## 这是什么

一个**开箱即用的局域网多人联机游戏**：电脑上跑一个 exe，手机扫码或开 App 就能进房间一起玩。

技术上它是一个**分布式应用**，不是玩具 demo：

- **手写 WebSocket 服务端** —— 零 `ws` 依赖，自己实现 RFC6455 握手与帧编解码
- **规则引擎纯函数化** —— 随机源与时钟由调用方注入，同一份代码在服务端作权威判定、在客户端作单机对局
- **自定义 UDP 发现协议** —— 手机 App 打开就列出局域网服务器，一个地址都不用输
- **594 条自动化断言** —— 真实 socket / 真实进程通信，全程不做网络 mock

## 三种玩法模式

| | 死亡轮盘 `solo` | 对赌轮盘 `turn` | 死神追猎 `race` |
|---|---|---|---|
| 运行位置 | 客户端本地 | 服务端 | 服务端 |
| 轮盘 | 各自独立 | **全场共享** | 各自独立 |
| 初始血量 | 7 | 15 | 10 |
| 死亡概率 | 随转数递增 | 固定 30/30/10/10/20 | 固定 |
| 结束条件 | 死 或 扣血合计 100% | 只剩一人 | 只剩一人 / 100 轮比用时 |

道具：护符 100 · 药水 300 · 减少转数 200（−5，限 3）· 香蕉皮 150（仅 race）。

## 快速开始

### 只玩单机（零配置）

直接用浏览器打开 `roulette-wheel.html` 即可，不需要服务端。

### 局域网联机

```bash
# 1. 启动服务端（默认端口 8080，可选房间码）
node server.js 8080

# 2. 同一 Wi-Fi 下，手机浏览器打开服务端首页 start.html
#    或装 Android APK —— App 会自动列出局域网内的服务器，点一下就能连
```

启动后终端会打印本机地址与服务器编号（形如 `K7Q2-M4`）。

### 服务端参数

```bash
node server.js [端口] [房间码] [管理台端口]
```

| 参数 | 默认 | 说明 |
|---|---|---|
| 端口 | `8080` | 游戏 WebSocket 端口 |
| 房间码 | `584520` | 门禁凭证，**只挡新加入的人**；`RR_ROOM_CODE=''` 表示无房间码 |
| 管理台端口 | 端口 + 1000 | **仅绑定 `127.0.0.1`**，外部无法访问 |

环境变量：`RR_STATE`（存档路径）、`RR_RULES`（规则覆盖路径）、`RR_ROOM_CODE`、`RR_NO_DISCOVERY=1`（关闭 UDP 发现）、`RR_DISCOVERY_PORT`。

### Android 端

```bash
cd build && node build-android.js
```

产物在 `D:/Trae打包文件/生死转盘/生死转盘-手机版.apk`。

### Windows 单文件 exe

```bash
cd build && node build-pc.js          # 服务端
cd build && node build-pc-client.js   # 客户端
```

用 Node 22 的 **SEA**（Single Executable Application）+ `postject` 注入实现：
规则引擎内联为 `EMBEDDED_ENGINE`、网页资源转 base64 内联为 `EMBEDDED_ASSETS`，
`server.js` 靠 `typeof` 探测自动适配「源码运行 / 打包运行」两种形态——**同一份代码，两处运行，零差异**。

## 架构

### 规则与表现彻底分离

`engine.js` 里**没有 DOM、没有 `setTimeout`、没有 `Math.random`**。随机源 `rng` 与时钟 `now`
都由调用方注入，因此：

- 在服务端跑 → **权威判定**
- 在客户端跑 → 单机对局 / 预测 / 回放

所有对局变化都表达为 `events` 数组，**客户端只认 events 播动画，绝不自己算结果**——
这是联机防作弊与防状态不同步的关键。

### 三层可靠性机制

| 机制 | 实现 |
|---|---|
| 服务端权威 | 唯一产生随机数的地方（服务端 crypto），客户端拿不到也预知不了 |
| 掉线封存 | 玩家掉线 → 对局封存、全员回来 → 解封，**封存时长不计入存活时间** |
| 房主自动迁移 | 房主掉线时转给「在线且编号最小」的成员，避免全房间死锁 |
| 看门狗 / 限流 | 45 秒无响应自动判定掉线；60 条/秒限流 |

### UDP 局域网发现（自定义 RRSP 协议）

```
客户端每 2.5s 广播 {"RRSP":1,"q":"who"} → 服务端单播回一张卡片
服务端每 3s  主动广播心跳（兜底）
```

**为什么双路**：① 要求**电脑**放行入站 UDP 广播；② 要求**手机**能收到入站广播。
Windows 首次运行会弹防火墙授权，用户点「取消」的话 ① 整条就废了——这时候只有 ② 能救。
两条路的要求正好互补，所以都留着。卡片带 9 秒 TTL，两条路共用一张表，避免后到的挤掉先到的。

> **为什么必须在原生层做**：浏览器 / WebView 里的 JS **发不了 UDP 广播**（安全沙箱）。
> 所以 Android 端必须用 `DatagramSocket` 原生实现，再经 `@JavascriptInterface` 桥回传页面。

```bash
node build/run-all.js        # 全量回归（当前 680 条全绿）
node run-test.js <输出文件> <脚本名>   # 单跑某个脚本
```

|---|---|---|
| `client-mp-test.js` | 256 | 移动端协议交互 |
| `test-online.js` | 150 | 端到端：拉起真 server.js + 真 WebSocket 客户端跑完整流程 |
| `engine-modes-test.js` | 125 | 三种模式规则 |
| `discovery-test.js` | 56 | UDP 发现协议，全程真 socket，不 mock 网络 |
| `engine-test.js` | 19 | **等价性测试** + 蒙特卡洛 |
| `client-solo-test.js` | 24 | 单机流程 |
| 真机验收（`build/verify-*.js`） | 50 | APK / 服务端 / 管理台 / 隧道 |

另附 10 个 `sim-*.js` 数值模拟脚本，用于验证转数分布、通关率、僵局与竞速。

### 两种值得单独说的测法

**① 等价性测试（golden master）**
把规则逻辑抽出引擎之前，把旧实现**逐行转录成一份独立参考实现**，用**同一个随机种子**
驱动两套代码，最终状态必须逐字段一致。这才敢宣称「抽出引擎后规则一个字节都没走样」。

**② 蒙特卡洛数值验证**
带策略跑 5 万局，看通关率、平均转数与评价分布，确认数量级合理，
同时作为以后调数值的基准线。改「利息封顶」或「71 转翻倍」这类规则时，
必须重跑 `sim-v10-stalemate.js` 做 2×2 消融。

### 一条踩坑教训

> **Node 内置 WebSocket 连失败只给 `error`、不给 `close`；真浏览器两个都给。**
> ⇒ 「连不上 → 自动重连」这段逻辑在测试里**从来没被真正触发过**，无限重连才能躲在全绿后面。
> 后来测试侧给 WS 包了一层：补上 error 之后必跟的 close，并记录每次连接的真实目标 url
> （不看真实 url，根本测不出「点了卡片却连去别处」）。
>
> **假替身比真东西宽容的地方，就是 bug 的藏身处。**

## 安全设计

- **管理台物理隔离**：独立端口（+1000）+ 仅 `bind 127.0.0.1` + `admin.html` 不进静态白名单。
  判 IP / 判 Host 都没用——**直接不暴露**。
- **状态存档不在静态白名单**，绝不通过 HTTP 路径访问。
- **操作日志绝不记地址与房间码**（玩家会整段贴群里），字段白名单里根本没有 `code`。
- 客户端日志 256KB 封顶、文件名时间戳自生成、名字只进正文不当文件名（防路径穿越）。
- 规则覆盖走 `Engine.configure(ov)`：只认白名单字段 + 钳制 + 概率和必须为 100，
  **校验失败整条拒绝并回滚**。
