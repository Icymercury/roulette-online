# V14 · 异地接入：三条通路 + 三处地址解析硬伤

> 时间：2026-09-24
> 触发：赐红问「校园网跟公网不通，外地朋友怎么连服务器（手机和 PC 分别怎么弄）」
> 前置：V13 已实测确认 —— 校园网**阻断二层广播**（`255.255.255.255` 与子网广播都到不了），
> 但三层单播完好（手机 `nc` 拿得到页面，单播投卡 App 完整显示）。

---

## 一、结论先说：三条路**不是三选一**

服务端监听的是 `0.0.0.0:8080`，所以下面三个地址**同时有效**：

| 通路 | 拿到的地址长什么样 | 谁从哪条路进来都行 |
|---|---|---|
| 局域网（同 WiFi / 校园网） | `10.113.132.95:8080` | 同城、同网 |
| 异地组网（Tailscale / ZeroTier） | `100.64.x.x:8080` 或虚拟网 IP | 装了同一个组网软件的人 |
| 内网穿透（cpolar / 花生壳） | `https://xxx.cpolar.cn` | **任何人，浏览器打开就行** |

**是加法，不是选择题。** 房主可以全开，朋友挑一条能通的。

---

## 二、朋友端到底怎么填

### 朋友用手机（APK）

| 通路 | 操作 |
|---|---|
| 同 WiFi / 同校园网 | 打开 App，**首页直接列出服务器**，点一下进（V12 的自动发现） |
| 异地组网 | 手机装 Tailscale / ZeroTier → 加入同一个网络 → App 里「异地加入 · 手动填地址」填 `100.64.x.x:8080` |
| 内网穿透 | App 里「异地加入 · 手动填地址」→ **房主给什么就整条粘进来**（带 `https://` 也行） |

### 朋友用 PC

| 通路 | 操作 |
|---|---|
| 同网 | 双击 `生死转盘-客户端.exe` → 列表里点一台 |
| 异地组网 | 客户端 exe 的手动框填 `100.64.x.x:8080` |
| 内网穿透 | **最省事：直接用浏览器打开房主给的网址就能玩**，地址自动填好，点「连接」进房间；<br>也可以把网址填进客户端 exe 的手动框 |

### 内网穿透有个隐藏好处

`client.html` 里有一段逻辑：页面从 http(s) 地址加载时，会把 `location.host` 自动填进地址框。
所以朋友用浏览器打开 `https://xxx.cpolar.cn` —— **地址已经填好了，点一下就进房间**。
零安装、零输入。

## 三、三条路的代价（调研所得）

| | 不依赖打洞 | 要装软件 | 自动发现能用吗 | 主要代价 |
|---|---|---|---|---|
| **内网穿透** | ✅ 唯一不依赖 | ❌ 朋友什么都不用装 | 不能（只能手填 / 点链接） | 免费版域名可能每天变，每次开黑要重发地址；1 Mbps 限速对本项目够用 |
| **Tailscale** | ❌ | 两边都要装 + 注册 | ❌ 三层网络不转发广播 | 国内 DERP 中继（港/日）比 ZeroTier 稳；校园网可能拦 UDP 打洞 → 退到中继 |
| **ZeroTier** | ❌ | 两边都要装 + 输网络号 | ✅ **唯一转发二层广播** | 打洞失败就走海外中继、限速约 500 KB/s；**校园网正是打洞失败率最高的环境** |

**为什么限速不是问题**：游戏页面才 94 KB，之后全是很小的 JSON 帧。瓶颈是延迟不是带宽。
实测国内穿透平均 48 ms，完全够玩。

**本项目最推荐：内网穿透** —— 它是唯一绕开「打洞」和「广播」两个不确定因素的路。

## 四、本轮改了什么

### 三处会当场撞死的硬伤（地址解析）

原来的 `normalizeAddr()` 是按「局域网 IP」写的：见到没端口就**一律补 `:8080`**。
遇到公网域名就是死地址。现在统一成 `parseAddr(raw) → { addr, secure }`，三条规则：

| 输入 | 旧行为 | 新行为 |
|---|---|---|
| `https://xxx.cpolar.cn` | `xxx.cpolar.cn:8080` ❌（穿透给的是 443） | `xxx.cpolar.cn:443` + `wss` ✅ |
| `http://xxx.cpolar.cn` | `xxx.cpolar.cn:8080` ❌ | `xxx.cpolar.cn:80` + `ws` ✅ |
| `wss://host:9000` | 只剥协议，端口对但**不知道要加密** | `secure=true`，走 `wss` ✅ |
| `192.168.1.5` | `192.168.1.5:8080` ✅ | 不变（局域网老行为不许退化）✅ |
| `100.64.3.7` | `100.64.3.7:8080` ✅ | 不变 ✅ |
| 裸域名（无协议） | 补 8080 ❌ | **跟随页面协议**：https 页面 → `wss:443`，否则 `ws:80` ✅ |

三处改动点：

1. **`client.html`** — 新增 `parseAddr()` / `altOf()` / `canonicalOf()`；
   `connect()` 拆出 `openSocket(addr, secure)`；
   `ADDR_KEY` 存 `wss://host:port`（能还原「加密」这个事实，下次回填不会退化成明文）。
2. **`pc-client.js`** — 同一套 `parseAddr()`；`/open` 与开窗**不再硬拼 `http://`**，
   改成按 `secure` 拼 `https://` 或 `http://`。选择页提示也改成「房主给什么就整条粘进来」。
3. **`server.js`** — 横幅新增「── 外地的朋友怎么连 ──」分区。

### 手机端 `file://` 推不出协议 → 加了「换一种再试一次」

手机 App 里页面是 `file://`，`location.protocol` 永远是 `file:`，
所以朋友只填了一串域名时，**加密还是明文是猜的**。

现在：猜错一次就自动换另一种（自动补的端口跟着 80↔443 一起换），**只换一次，绝不来回翻**；
连上之后把对的那个存进 `ADDR_KEY`，下次直接用对的。

### 服务端横幅分区

```
  ★ 别人连这一行 —— 同一个 WiFi / 校园网下，照抄，不要加 http:// ：
        10.113.132.95:8080        ← 网卡：WLAN

  ── 外地的朋友怎么连 ────────────────────────────
  ○ 没检测到虚拟网卡 —— 外地朋友现在还连不进来。三条路任选其一：
    ① 装 Tailscale（两边都装、登同一账号）→ 重启本程序，这里会多出一行地址；
    ② 装 ZeroTier（两边都装、加入同一个网络 ID）→ 同上；
    ③ 内网穿透（cpolar / 花生壳等），把本机的 8080 端口映射出去 → 拿到一个公网网址，
       直接发给朋友：他用浏览器打开就能玩，地址会自动填好，点一下进房间。
```

装了组网软件后，`lanAddrs()` 会把虚拟网卡标记成 `kind:'vpn'`，横幅自动变成
`★ 异地朋友连这一行（虚拟网：Tailscale / ZeroTier 等）` 并列出地址。

**为什么必须分开印**：局域网地址外地根本连不上，但它一直霸占最显眼那一行 ——
房主照着报，朋友必然失败。这是 V11 那次「印了 169.254 死地址」的同一类问题。

### 顺手修的两个构建期坑

- `build-pc.js` / `build-pc-client.js`：**正在运行的 exe 在 Windows 上被锁住**，
  覆盖会 `EBUSY` 把整个打包炸掉。现在检测到锁就改输出 `-新.exe` 并提示，构建不再死。
- `test-online.js`：攒钱那段上限 25 次，金币格 20% ⇒ **约 6% 概率假失败**。
  上限提到 60 次，并对局一结束就停手（免得为了攒钱把人转死）。

## 六、风险与未验证

1. 🟡 **内网穿透这条路一次都没真跑过** —— 没有真实隧道可供测试。
   代码层已按判据钉死（端口不补 8080、协议跟随页面），但「cpolar 转发 WebSocket 升级」
   这个环节要实际连一次才知道。
2. 🟡 **ZeroTier 打洞是 DIRECT 还是 RELAY 没验过** —— 校园网是失败率最高的环境。
   赌赢了自动发现直接复活，赌输了只能走穿透。
3. 穿透的免费域名可能每天变 → **每次开黑要重发一次地址**。这是服务的限制，改不了。
