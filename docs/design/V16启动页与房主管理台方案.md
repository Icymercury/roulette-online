
### 3. `admin.html`（新增，房主管理台）

**进门流程与鉴权（🔴 必须先做的一层）：**

```
连 WebSocket → 发 { type:'adminLogin', pass } 
   → 服务端校验：pass === room.code  且  client.id === room.hostId
   → 通过：下发 rules 快照 + 当前公网网址
   → 不通过：rejected（not-host / bad-code）
```
- **没设房间码 ⇒ 管理台直接拒绝进入**，先逼房主设码。理由：管理台能改规则，用空口令守等于不守。
- 房主判定复用现成的 `boss = client.id === room.hostId`（`server.js:831`）。

**页面内容：**
1. **连接信息**：服务器名称、编号、房间码（改这三项复用现有 `config` 指令）。
2. **外地朋友的网址**：显示服务端代抓到的 cpolar 网址 + 一键复制。（🔴 页面是 https 时，浏览器**不能**去 fetch `http://127.0.0.1:4042` —— 混合内容会被拦。所以必须由服务端代抓。）
3. **规则分区**（三个模式各一组）：
   - 血上限、死神节点转数、镰刀档位（`71→1 / 81→2 / 91→3`）
   - 转盘概率（联机=固定 5 项数组；单机=曲线开关）
   - 金币：转到金币格收益、利息档位
   - 商城：每个道具的是否在售、价格、次数上限
   - 涨价起始转数
4. **护栏 UI**：
   - 🔴 危险项标红：**利息本金封顶 500**、**71 转后涨价**、**血上限**。改这三处弹确认框，并提示「改完请重跑 `sim-v10-stalemate.js`」。
   - 「恢复默认」按钮（一键清空覆盖层）。
   - 保存时若服务端在局中 → 提示「新规则将在**下一局**生效」。

### 4. 规则改写的引擎改造（`engine.js`）

好消息：规则**不是散落的魔数**，已经集中在三张表里，改造量比预想小。

| 表 | 现在 | 可覆盖字段 |
|---|---|---|
| `SHOP` | 道具总表 | `price` / `limit` / `step` / `spins` |
| `NUM` | 金币与利息 | `GOLD_PER_PICK` / `INTEREST_PER` / `INTEREST_GAIN` / `PROBS_FIXED`（概率数组） |
| `PRESETS[mode]` | 三模式规则 | `hpMax` / `nodeFirst` / `nodeScythe` / `scythe.tiers` / `interest.cap` / `inflationFrom` / `shop[]` / `doomAt` / `target` |
| `probs(n)` | 单机曲线，**系数硬编码在函数里** | 把 5 组「基数 + 斜率 + 下限」提成 `PROBS_CURVE` 常量（唯一需要动函数的一处，小改） |

- 新增 `Engine.configure(overrides)`：深合并覆盖层。
- **字段白名单校验**：只认已知字段，未知字段忽略（防手改 json 把引擎搞崩）。
- **数值钳制**：血上限 1–99、价格 0–9999、概率数组**五项之和必须 = 100**（不合法直接拒绝并返回默认值）。

### 5. 服务端：规则落盘与同步
- `rules.json` 单独存盘（**不进白名单**）；启动时加载 → 注入引擎。
- 新增/扩展指令 `config` 的 `rules` 字段（仅房主，复用现有权限分支）。
- **同步**：`welcome` / `sync` 里带 `rules` 快照 → 客户端用它渲染商城价格、概率显示、血条上限。
- **局中改动**：写进 pending，当前局结束才切换；广播提示。
- **单人模式的规则来源**：默认用**内置默认**（离线可玩）。若本机开着服务端，单人页启动时拉一次 `/rules`（拿不到就用默认，并在界面上标注「自定义规则」/「默认规则」）。

### 6. 穿透网址进服务端横幅（② 的进阶版）
- `server.js` 启动后每 10 秒用 Node 侧 fetch 抓 `127.0.0.1:4042` 页面里的 `PublicUrl`（逻辑同已交付的 `build/tunnel-url.js`，Node 侧没有浏览器的混合内容限制）。
- 抓到就在横幅「外地的朋友」那一段下面多打一行网址；同时给 admin 页。
- 开关：`RR_NO_TUNNEL=1` 关掉。

## 四、风险与护栏（按危险程度排）

1. 🔴 **僵局两条命根子**：对赌轮盘的零僵局靠「利息本金封顶 500」+「71 转后每买一次翻倍」。房主随手改掉就可能造出打不完的局 ⇒ 标红 + 确认框 + 一键恢复 + 提示重跑压测。
2. 🔴 **管理台鉴权**：能改规则就必须卡死。房间码当口令，无码不许进。
3. 🔴 **`/` 语义变化**：连锁 5 个脚本（见上表），漏一个测试就红。
4. 🟡 **规则不同步**：所有客户端必须从服务端拿快照，否则出现"你看到的价格和我判的价格不一样"。
5. 🟡 **局中改规则**：只下一局生效，否则同局两种规则。
6. 🟡 **白名单**：`start.html` / `admin.html` 显式放行；`rules.json` / `state.json` 绝不放行（穿透暴露后这是唯一防线）。

## 六、还需要你拍板的三个小决定

1. **单人模式要不要吃服务端规则？** 我推荐：默认吃内置规则（离线可玩、零依赖），本机开着服务端时才同步，界面上标注用的是哪套。
2. **管理台要不要允许异地访问？** 穿透之后朋友也能打开 `/admin`。选项：A 房间码即可进（方便）/ B 只有本机（127.0.0.1）能进（更安全）。我推荐 **A + 记录谁改过**。
3. **要不要「预设方案」**（存三套自定义规则一键切换）？我建议这轮不做，等规则真用起来再说。
