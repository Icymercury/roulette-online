# V18.1 · 异地「填网址 + 房间码，点连接没反应」

2026-09-29 23:10 · 赐红报：「异地连接无法正常连接了，输入网址和房间码之后点击连接没有反应」。

结论：**真 bug，已修，两个产物已重打**。先说结论，再说是谁的锅。

---

## 一、现象复现

用真浏览器 + 真服务端跑了一遍（探针 `.workbuddy/tmp/probe-remote.js`）：

| 步骤 | 修复前 | 修复后 |
|---|---|---|
| ① 填错房间码，点「连接这个地址」 | 状态 **「已连接」**，还切到了游戏页 —— 其实被挡在门外 | 状态 **「房间码不对」**，退回连接页 |
| ② 改成正确房间码，再点一次 | 状态变 **「已离开」**，日志里**一句「正在连接」都没有** | 状态「已连接」，进大厅（编号 1） |

第 ② 步就是赐红说的"点了没反应"：玩家点的是"连接"，实际执行的是"断开"，
界面没有任何"正在连接"的反馈，只是默默回到连接页。

---

## 二、根因（两个叠在一起才发作）

### 🔴 根因一：`joinBtn` 把「已经连着」当成「想断开」

```js
$('joinBtn').onclick = () => {
  if (ws && ws.readyState === 1) { manualClose = true; ws.close(); setConn('已离开', 'off'); return; }
  connect();
};
```

**归因：这句不是 V18 新写的** —— 9-24 那版 `client.html`（`.workbuddy/tmp/tunnel-stage/client.html:2092`）
里就已经在了。它是被 V17 的界面重构**推到聚光灯下**的：

- 局域网：点服务器卡片 → `pickServer()` → 要码就弹浮层 → `codeYes` → `connect()`。
  **这条路上根本没那句守卫**，所以带房间码的局域网连接一直是好的。
- 异地：**只能**手填地址、**只能**点 `joinBtn` ⇒ 整条异地路被这一句堵死。

### 🔴 根因二：房间码不对时，服务端不关连接

`server.js:1096`：

```js
if (msg.type === 'join') {
  if (room.code && msg.pass !== room.code) {
    sendJSON(client, { type: 'rejected', reason: 'bad-room-code' });
    return;                      // ← 回完就走，连接原样留着
  }
```

于是那条 WebSocket 一直是 `OPEN`：

1. 界面显示"已连接"、还切到了游戏页 —— 玩家不知道自己被挡在门外；
2. 连接一直 OPEN ⇒ 根因一那句守卫**有条件发作**（`readyState === 1` 成立）。

两个缺一个都不至于"点了没反应"，凑一起才致命。

---

## 三、修法

### ① 删掉守卫（`client.html`）

按钮的语义就是「连这个地址」。换服务器就换服务器 —— `openSocket()` 自己会
把旧连接顶掉（`dropped` + `close`），不需要按钮代劳。

```js
$('joinBtn').onclick = () => {
  connect();
};
```

### ② 房间码不对时自己收掉连接（`client.html`）

```js
if (m.reason === 'bad-room-code') {
  log('房间码不对 —— 问房主要正确的码，改完再点一次「连接这个地址」', '#e5383b');
  manualConn = '房间码不对';       // 新增：让 onclose 显示这句，而不是「已离开」
  manualClose = true;
  joined = false; myId = null; view = null;
  try { if (ws) ws.close(); } catch (e) {}
  render();
  return;
}
```

配套新增 `manualConn`（用完即清），`onclose` 的 `manualClose` 分支改成
`setConn(manualConn || '已离开', 'off')`。

## 五、🟡 顺带发现 → ✅ 已修（V18.2，赐红一句「改」）

`server.js` 的 **`argv[3]` 曾被两个功能抢**：

| 位置 | 原先把 argv[3] 当成 |
|---|---|
| `server.js:44` | 房间码 |
| `server.js:794` | **管理端口**（`Number(argv[3]) \|\| PORT+1000`） |

⇒ `node server.js 8080 584520`（命令行设房间码）会让管理台去 listen 584520，
直接 `ERR_SOCKET_BAD_PORT` **起不来**。房主双击 exe 不受影响（没 argv），
但凡有人在命令行带码启动就中招。

**现在的分工（已改）**：
- `argv[3]` = **房间码**（保持原样）
- 管理台端口 = **`RR_ADMIN_PORT` 环境变量 > `argv[4]` > `PORT + 1000`（默认）**

⇒ `node server.js 8080 584520` 现在能正常起来，管理台在 9080。
`test-online.js` 新增 5 条断言钉死这件事（含「把旧写法放回源码 ⇒ 5 条全红」的有牙验证）。
