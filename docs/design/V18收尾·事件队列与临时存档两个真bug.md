## 一、`client.html`：回到大厅会把后面的演出整批吃掉（玩家可见）

### 现象

收尾跑回归时 `client-mp-test` 稳定挂在 §⑥b：

```
✗ 测试中断：等待超时：A 的记录里播出「退出本局」
```

而且躲猫猫：**单独 `node run-test.js` 跑必绿（218/0），被另一个 node 进程拉起来必红（191/1）**。

### 排查

1. 换了 pipe / inherit 两种 stdio 都是红的 ⇒ 跟 stdout 无关，不是 runner 的锅。
2. 给假 WebSocket 套个记录器 ⇒ 服务端**确实推过** `sync:lobby / sync:start / sync:watch / sync:leave|over`。
3. 再看客户端内部（`probe()` 能拿到 `playing` / `queue`）：

```
playing=false
queue=[]
记录 = [001] 回到大厅，可以重新配置        ← 只有一条
```

消息收到了、队列空了、没在播，可该播的一条都没落到记录里。

### 真因

`step()` 里 **`case 'lobby'`（还有 `case 'start'`）写了一句 `queue.length = 0`**。

队列是**从头往后**取的：轮到某条事件时，排在它前面的早就播完了 ——
这句唯一能清掉的，是**排在它后面、还没播的新事件**。

平时看不出来，因为队列不积压时 `lobby` 一到就被立刻消费、队列本来就是空的。
可一旦前面积压了上一局的演出（机器慢一点，或者玩家连点多几下就会出现），
`lobby` 会晚几十毫秒才轮到执行，那时它就把紧跟其后的 `start / watch / leave / over` 一起砍了。

**玩家侧的表现**：回大厅重开一局之后，界面放完就没了 ——
没有「赌局开始」、没有结算、没有「XX 退出了本局」，看着像卡住。

### 修法

1. 两处 `queue.length = 0` 都删掉。注释里写清楚了为什么不许再写回去
   （要丢"上一局的残留"，正确做法是按时间戳过滤，不是把后面的一起砍掉）。
2. **`drain()` 加了 try/catch 兜住 `step()` 的异常**。
   以前 `step()` 里抛异常 ⇒ 下一行 `setTimeout(drain, wait)` 排不上 ⇒ `playing` 永远是 `true`
   ⇒ 从此以后服务端推来的任何事件都播不出来 —— 界面看着还连着，其实已经哑了。
   现在异常会往记录里写一条「⚠ 演出中断」，下一条照常播。

### 新增断言（`client-mp-test` §⑥b，2 条）

先连点几次把队列**压起来**，再回大厅重开一局，等队列排空后断言「赌局开始」还在记录里。

写这条断言本身踩了两个坑，都值得记住：

| 版本 | 问题 | 修正 |
|---|---|---|
| v1 | 直接正则 `/赌局开始/`，命中的是**上一局**留在记录里的那条 ⇒ bug 在也能通过 | 先等「回到大厅」真的播出来（它会清空记录），再看新的补不补得上 |
| v2 | 用 `waitFor(…, 15000)` 赌墙钟 ⇒ 积压深度随机器快慢变化，慢机器上偶发假红 | 改成等**确定性条件**：`queue.length === 0 && !playing` |

v1 改完之后**手动把 bug 放回源码跑了一次确认它会红**（219/1，红的位置和诊断完全吻合）——
没有这一步，我加的就是一条假断言。

## 二、临时存档 PID 复用污染（另一批随机红的来源）

### 现象

另一轮回归在第 67 条就红：

```
✗ 测试中断：等待超时：A 收到 welcome
```

还有一轮挂在真机验收 `verify-live`：11 通过 / 6 失败，第一条就是「大厅浮层弹出（真 WebSocket 通了）」。

### 真因

六套测试的临时存档都用 **`RR_STATE = …-` + `process.pid`** 命名。
Windows 上 PID 很快被复用 ⇒ 新的一轮捡到上一轮留下的脏存档，
**里面房间可能还停在"局中"** ⇒ 新连接拿不到 `welcome`，只收到「要不要进来观战」的邀请。

症状跟"网络炸了"一模一样，排查方向很容易跑偏。

### 修法

`test-online` / `client-mp` / `discovery` / `verify-live` / `verify-admin`
/ `build-pc` / `build-pc-client` 七处统一改成：

```js
process.pid + '-' + Date.now().toString(36)
```

**运行内稳定**（服务端重启要验"恢复"，同一轮里必须是同一个文件），**跨运行唯一**。
