## 二、根因

### 坑 1 · 服务端横幅把「死地址」印在了最前面

`server.js` 的 `lanAddrs()` 只滤掉了 `internal`（回环）。问题是 Windows 上
蓝牙、Hyper-V、WSL、没插网线的以太网口**各自都会分到一个 IPv4**；
其中**没拿到 DHCP 租约**的网卡会分到 `169.254.x.x`（业界叫 APIPA）——这种地址**永远连不上**。

你机器上的实际情况（我实测出来的）：

```
169.254.228.153  <- 蓝牙网络连接 2      ← 死地址，排第 1
169.254.240.177  <- 以太网 2           ← 死地址
169.254.51.173   <- 本地连接* 2        ← 死地址
169.254.117.95   <- 以太网             ← 死地址
10.113.132.95    <- WLAN              ← 唯一能用的，排最后
```

横幅把这 5 条**全都印了出来**，而唯一能用的那条**排在最末**。
你照着第一条输 → 必然连不上。

**修法**：`lanAddrs()` 直接扔掉 `169.254/16`，再按「物理网卡 + 私网段」打分排序。
横幅现在只把最优的一条放大印出来，标成 `★ 别人连这一行`，其余降级成「一般用不上」。

现在的横幅长这样：

```
  生死转盘 · 联机服务器 v5
  ────────────────────────────────────────
  本机打开：      http://localhost:8080（双击本程序会自动开）

  ★ 别人连这一行 —— 手机 App / 别的电脑照抄，不要加 http:// ：

        10.113.132.95:8080        ← 网卡：WLAN

  房间码：        （无，任何人可加入；房主可在房间里设）
```

### 坑 2 · 横幅印 `http://ip:8080`，但输入端要的是裸 `ip:8080`

`client.html` 原来是这么拼的：

```js
const url = proto + '://' + addr;      // addr 原样拼
```

你复制整行 `http://10.113.132.95:8080` 贴进去 → 拼成 `ws://http://10.113.132.95:8080` → **必错**。

**修法**：新增 `normalizeAddr()`，连接前统一清洗：

| 你填的 | 清洗成 |
|---|---|
| `http://10.0.0.5:8080` | `10.0.0.5:8080` |
| `ws://10.0.0.5:8080` | `10.0.0.5:8080` |
| `http://10.0.0.5:9000/` | `10.0.0.5:9000` |
| `10.0.0.5` | `10.0.0.5:8080`（自动补默认端口） |
| `12345` / 空 | 判定为看不懂，当场提示 |

顺手把输入框的提示文案改成「如 192.168.1.5:8080，**别加 http://**」。

### 第三种可能（我没法替你排除）

你的地址是 `10.113.132.95`（WLAN，10 网段），**看着像校园网或公共 WiFi**。
这类网络经常开 **AP 隔离**（客户端隔离）——同一个 WiFi 下的设备**互相看不见**。
如果是这种情况，跟我们的代码一点关系都没有。

**30 秒自检**：手机浏览器直接打开 `http://10.113.132.95:8080`

- **打得开** → 网络是通的，问题在我们 App 里（那我已经修了，装新 APK 即可）
- **打不开** → 防火墙 或 AP 隔离。防火墙就点「允许」；AP 隔离只能改网络环境

AP 隔离的解法只有两个：**用手机开热点让电脑连**，或者走 **Tailscale**。
另外服务端横幅里也把这三步自检印出来了，以后不用问我。

## 三、你提的三件事，逐条回答

### ① 「是不是应该把客户端和服务端分开」

**代码上早就分开了。**

- `server.js` = 服务端（只 PC 跑）
- `client.html` + `engine.js` = 客户端
- **APK 里只装了客户端**（`assets/www/` 下就 client.html / engine.js / 单机页）
- **exe 里只装了服务端**

你觉得"像网页版"，**不是因为架构没分，是因为入口是一个"填 IP 的表单"**。
换言之：要改的是**入口的那个界面**，不是架构。

### ② 「用服务器编号 + 名称 + 房间码 来连接」—— 这里有个硬伤

**设备自定的编号是「名字」，不是「地址」。**

客户端拿到 `K7Q2-M4` 这个编号后，**没有任何办法把它变成 `10.113.132.95:8080`**。
中间必须有一个"查号台"（目录服务）。这不是实现难度问题，是**逻辑上不完整**——
就像你知道一个人叫"张三"，但不知道他住哪，你没法去找他。

所以只有两条路：

**路 A · 同网段广播发现（零成本，我建议先做这个）**

房主的服务端每隔 1~2 秒往局域网广播一次"我是谁"（UDP）。客户端 App 一打开就收到，
直接列出当前能连的服务器：

```
┌────────────────────────────────────┐
│  🎲  阿红的房间                     │
│      K7Q2-M4 · 3 人在线 · 已开局     │
├────────────────────────────────────┤
│  🎲  老王的局                       │
│      P3X9-Q1 · 1 人在线 · 大厅中     │
└────────────────────────────────────┘
            [ 手动输入地址 ]   ← 折叠起来，跨网段时才用
```

点一下 → 输房间码 → 进去。**一个字符都不用输 IP。**

- 成本：0。不用买任何东西，不用域名，不用运维。
- 局限：**必须在同一个 WiFi / 路由器下**。

**路 B · 公网目录服务（能跨网络，但成本比想象高）**

要让"任何网络下只输编号就能连"，必须有一台**公网服务器**当中转。而且——

> ⚠️ 中国家庭宽带绝大多数**没有公网 IPv4**（NAT 后面）。所以"目录只负责告诉对方地址"
> 这条路走不通，只能让**所有游戏流量都从那台服务器中转**。
> 那就不是"几十块一年"的事：要带宽、要扛延迟、要运维、要防滥用。
> 这是**另一个项目**，不是这个游戏的一个功能。

**我的建议**：跨网络的需求**不要自建**，用 **Tailscale**（免费、零运维、
每台设备一个固定 IP，服务端横幅已经会印 Tailscale 地址）。客户端 App 里加一个
「远程加入」入口，输一次 Tailscale 地址就记住。这能覆盖 99% 的"朋友不在一个 WiFi"场景。

**如果你确实想要"任何网络只输一个号"**，我也能做，但那是要做中继服务，
得你先决定掏不掏服务器钱。

### ③ 「链接加密改形式」

分两件事说：

- **「改形式」**（界面上不再出现 `ws://192.168.x.x` 这种字符串）—— ✅ 值得做，
  而且**路 A 会顺手解决它**：有了服务器列表，用户从头到尾看不到 IP。
- **「加密」**（真上 TLS）—— ❌ **我不建议在局域网里做**。
  理由：局域网内数据本来就不出你家的路由器；上自签证书会导致手机每次弹出安全警告，
  体验反而更差。真需要加密的场景是跨公网，那时候用 Tailscale（它本身就加密）。

**唯一值得做的加固是「房间码」**——它才是真正的门禁，防止同一个网络里的陌生人乱入。
`server.js` 里已经有 `room.code` 的基础设施，本轮把它接到 App 界面上。

## 四、关于「独立软件的形式」

**必须挑明一件事**：如果要求"把里面的网页换成原生安卓控件"，
那是把**整个游戏 UI**（转盘 SVG、动画、商店、观战面板、事件日志）用 Java 重写一遍——
几周工作量，之后**每个改动都要写两遍**，而**用户看不出任何区别**
（微信、淘宝里的界面全是 WebView，没人分得出）。

**"独立软件"的观感靠的是入口和图标，不是渲染引擎。** 所以正确的做法是：

1. 打开 App → 直接是**服务器列表**（扫描到的）+ 房间码输入 + 服务器名
2. 配启动图 / 应用名 / 图标
3. 界面上不出现任何 IP、`ws://`、`http://` 字符串
4. 猜不到的地址，收进「手动输入」折叠区

这样观感就是独立 App，成本是路 A 的一部分。

## 八、仍需你定夺

**连接方式走哪条路？**

- **路 A（推荐）**：局域网 UDP 广播自动发现 + 服务器名 + 房间码 + 设备编号（只作显示）
- **路 A + Tailscale 入口**：再加一个「远程加入」手动入口，覆盖异地朋友
- **路 B（自建中继）**：真正"任何网络只输编号"，但需要你出公网服务器 + 域名 + 流量成本

这是唯一一个会影响后面所有工作量的岔路口，所以先问你，不擅自开工。
