# V18.3 · 为什么"点了没反应"

赐红发来一份真实的操作日志（2026-09-30 01:12，手机端导出）。
日志里他**在本机、页面就是从服务器加载的**，却连了 57 秒、点了十几下都没进去。
逐行对照源码，挖出三个叠在一起的 bug —— 界面上的表现恰好都是"点了没反应"。

## 二、Bug ①：卡片被地址框里残留的旧地址劫持（最严重）

`connect()` 里的优先级是"**手填的优先**"：

```js
const typed = $('addr').value.trim();
const raw = typed || pendingAddr;      // ← 只要框里有东西，卡片就永远用不上
```

`pickServer()`（点卡片走的就是它）设完 `pendingAddr` 就调 `connect()`，
而地址框里只要**曾经**手填过一次，之后**点任何卡片都还在连那个旧地址**。

日志里 01:12:33～45 连点 `#srvList` 四张卡（含"本页就是这个服务器"），
记的全是「准备连接：手填的地址」—— 卡片形同虚设。
这就是"点什么都没反应"的直接来源。

### 修法

- `connect(force)`：**点卡片 / 点「进 入」/ 房间码浮层点确定**时，把目标显式传进来压过地址框。
- `pickServer()` 里新增 `dropTypedAddr()`：点卡片 = 明确换目标，顺手清掉地址框里的旧值
  （不清的话下次点卡片还会被它劫持），并给一句提示说明"那个旧地址已清掉"。
- `codeYes`（要房间码那条路）同样传 `pendingAddr`。

## 三、Bug ②：连不上就永远撞下去（3 秒一次，没有尽头）

`onclose` 里无条件 `reconnectTimer = setTimeout(connect, 3000)`。
只有"进来时自动连上次那台"失败才被 `giveUpAutoJoin()` 收住；
**玩家自己点的连接失败，就进入了无限重连**。

日志里从 01:11:53 一路撞到 01:12:50，十几轮。
界面一直在「恢复中… / 已断开 / 已离开」之间跳 —— 玩家当然以为卡死。

### 修法

- 新增 `reconnectFails` / `RECONNECT_MAX = 3`：连续失败 3 次就停手，
  状态写「**没连上**」，退回连接页，并明确告诉他"地址对不对、服务端开着吗"。
- 连上（`onopen`）清零；玩家**自己点按钮**也清零（否则他再点还是立刻停手）。
- 重连必须**显式带上刚才那台**（`connect(again, '重连刚才那台', true)`）：
  不然地址框里残留的旧值会把它劫持到别处（跟 Bug ① 同源）。

## 四、Bug ③：换协议重试被当成"玩家主动离开"

明文连不上 → 换加密再试一次，这一步要先 `ws.close()` 关掉旧的。
它走的是 `manualClose` 分支 ⇒ 状态被打成「**已离开**」、界面弹回连接页。

日志里每次换协议前都冒一条 `[状态] 已离开` —— 玩家根本没离开过。

### 修法

- 新增 `switchingProto`：换协议时的 close 是**我们自己**关的，
  状态保持「连接中」，界面不弹回连接页。
- 顺带修了一个相关的：`onclose` **只认一条连接的第一次 close**。
  重复的 close 会把"换协议"这个一次性标记吃掉，第二次被当成正常断开再计一次失败、
  再排一次重连 —— 结果换协议那条路根本跑不到（这个是在测试里才暴露出来的）。

## 五、另外两处顺手补的

| 位置 | 问题 | 处理 |
|---|---|---|
| `connect()` | 玩家连点按钮 ⇒ 1 秒开出五六条连接互相顶替，界面却毫无变化 | 同一台正在 CONNECTING 就忽略重复点击，并提示"正在连接中，稍等一下" |
| `onclose` | 有些环境 error 之后会再给一次 close ⇒ 落下两个重连定时器 | 设定时器前先 `clearTimeout` |

## 七、🔴 测试方法上的一个坑（这次才发现的）

**Node 内置的 WebSocket 连失败时只给 `error`，不给 `close`；真浏览器两个都给。**
也就是说，「连不上 → 自动重连」这一段代码在测试里**从来没被真正触发过** ——
所以无限重连这个 bug 能一直躲在全绿的测试后面。

现在测试侧给 WebSocket 包了一层，补上浏览器才有的行为
（`error` 之后必跟一次 `close`），并顺带记下每次连的目标地址 ——
**不看真实 url，根本测不出"点了卡片却连去别的地方"**。

同类教训（跟上次"断言取值撞默认值"是一路的）：
**假替身比真东西宽容的地方，就是 bug 的藏身处。**
