## 二、① 去掉 IP 暴露 —— 改了什么

### 之前的行为（就是你不喜欢的那个）

```js
if (savedAddr) $('addr').value = savedAddr;      // 上次连过的地址
else if (pageHost) $('addr').value = pageHost;   // ← 这个：一打开就把 IP 粘进地址框
```

PC 客户端打开的是 `http://10.113.132.95:8080/client.html`，`location.host` 天然就是你的 IP，
于是**地址框里写着 `10.113.132.95:8080`**。而且日志里还会印一整条
`正在连接 ws://10.113.132.95:8080` —— IP 和协议都在屏幕上。

这其实违反了我们自己在 V12 立过的规矩：**「界面上不出现任何 IP / 协议字符串」**。
V14 加 `location.host` 自动填充时把它破了。这轮补回去，而且立成硬规矩、钉进测试。

### 现在的行为

**地址只活在内存里（`pendingAddr`），界面上只显示「名字」。**

| 位置 | 之前 | 现在 |
|---|---|---|
| 地址输入框 | 自动填入 IP | **永远为空**（只装用户自己敲进去的东西） |
| 连接日志 | `正在连接 ws://10.113.132.95:8080` | `正在连接…` |
| 服务器列表 | 只有扫到的 | **多出两张卡**：「本页就是这个服务器」、「上次进过的房间」 |
| 点卡片 | 把 IP 填进地址框 | 地址进内存，卡片上只有名字 |

「本页就是这个服务器」那张卡很重要 —— 它让**朋友用浏览器打开穿透网址后仍然是点一下就进**，
只是现在点的是名字，不是 IP。

### 代码

`client.html`：
- 新增 `pendingAddr` / `autoJoin` 两个内部变量；新增 `addrOf()` / `knownCard()`。
- `pickServer()` 改为写 `pendingAddr`，不再碰地址框。
- `connect()` 改为 `const raw = $('addr').value.trim() || pendingAddr;`，
  并且**只有用户敲过才回写地址框**（否则等于把内存里的 IP 又摊出来）。
- `openSocket()` 的日志不再拼 URL。
- `init()` 里 `knownCards` 由「上次连过的 / 本页所在的」生成，`renderServers()` 渲染
  `knownCards.concat(discovered)`（注意：`onServers` 每轮整个替换 `discovered`，
  所以已知卡片必须单独放一份，否则会被冲掉）。

## 三、② C：记住上次那台 → 打开就直接进

- `init()` 末尾：`if (savedAddr) setTimeout(() => { autoJoin = true; connect(); }, 150);`
- 失败由新增的 `giveUpAutoJoin()` 收住：**停下来把入口还给玩家**，不会变成后台每 3 秒重试。
  （这条是必须的 —— 否则朋友半夜打开一次没连上，手机就在后台一直撞，看着像卡死。）
- 连上瞬间 `autoJoin = false`，之后正常断线照旧自动重连（你的角色会被原样恢复）。

测试（`client-mp-test.js` 新增 §⓪d，5 条）：
打开就自己连 ✓ · 卡片显示名字不显示地址 ✓ · 地址框仍为空 ✓ ·
连不上时停下来（日志出现「上次那台服务器现在没开着」）✓ ·
**放弃后不再反复重试**（等第二轮，错误日志次数没有继续涨）✓

## 四、③ A：内网穿透自检（`build/verify-tunnel.js`）

```
node build/verify-tunnel.js <地址>
例：node build/verify-tunnel.js https://abc123.cpolar.cn
```

11 条断言，最关键的是**⑤ WebSocket 升级有没有被隧道转发** —— 这是唯一从没验过的环节：
穿透服务通常只保证 HTTP 能通，`Upgrade` 头经常被中间层吃掉，
那就会出现「朋友打得开页面、却永远进不了房间」这种最难排查的半通状态。

| # | 验什么 |
|---|---|
| ① | 地址能不能解析成 `host:port` + 该不该加密 |
| ② | `/client.html` 200，而且是新版页面（含 `parseAddr`）、引的是相对路径 `engine.js` |
| ③ | `/engine.js` 200 |
| ④ ★ | `/server.js`、`/state.json` **必须 404** —— 穿透等于把 8080 暴露给公网，这条是源码和存档的唯一判据 |
| ⑤ ★ | 真连一次 WebSocket：`join → welcome` |
| ⑥ ★ | 真浏览器打开网址：转盘画出来了、`init()` 跑完了、**服务器列表里没有任何 IP** |

本地自测（起临时服务端跑一遍）：**11 通过 / 0 失败**。
⚠️ 本地自测证明的是**脚本本身是好的**，不等于真穿透隧道能过 WebSocket —— 这一步必须拿真网址跑。

**你需要做的**：注册 cpolar（或花生壳）→ 把本机 8080 映射出去 → 把网址给我 → 我一条命令验完。

## 七、评估：把服务端集成进 APK，让手机自己组局域网联机

**结论：技术上可行，但我建议现在不做。** 下面是拆开的理由。

### 要落地，得同时做成三件事

| # | 事 | 难度 | 说明 |
|---|---|---|---|
| ① | 安卓上跑 TCP：HTTP + WebSocket | **中** | `ServerSocket` 现成；WebSocket 要自己写握手（SHA-1 + Base64）和帧编解码（掩码/分片/ping-pong/关闭帧）。**有 Node 版可以逐行对照翻译**，约 400–600 行 Java。d8 那条老约束（不许匿名内部类）照着写顶层类就行 |
| ② | 安卓上跑 UDP 广播（服务端那半边） | **低** | `Discovery` 里已经在用了，真机日志 `heartbeat listening on 8099` 证明这套 API 在真机上能跑 |
| ③ | 安卓上跑 `engine.js` | **高（这是唯一的硬骨头）** | 安卓没有能直接用的 JS 引擎 |

### ③ 的三条路，只有一条值得走

**A. Java 只做传输层，规则层留在 WebView 里跑**（推荐）
Java 收到字节 → 把 JSON 喂给一个隐藏 WebView → WebView 回吐要发的 JSON。
`engine.js` 原地复用，**零移植**。
代价：消息往返全变异步（本地几十毫秒级，本游戏够用）；房主自己也要玩，得开两个页面。

**B. 塞一个 JS 引擎进 APK**（不推荐）
QuickJS 要 NDK（本机没有，且 d8 那条链已经很脆）；J2V8 让 APK 从 101 KB 涨到 ~30 MB；
Rhino 是纯 Java 但 ES6 支持不全，而且仍然缺 Node 的 `http/net/dgram` —— 还是得自己写。

**C. 用 Java 重写 `engine.js`**（强烈不建议）
1000+ 行规则代码。一旦规则有两份实现就会漂移 ——
**「规则只有一份」是这个项目从头到尾最值钱的一条**。以后每次改数值都得改两处、跑两套测试。

### 三个安卓特有的硬伤（这些才是真正劝退的点）

1. **后台存活**。安卓 8+ 限制后台服务，息屏几分钟就可能杀进程/断网。
   房主锁屏 = 整局没了。要缓解得上**前台服务 + 常驻通知**，还要引导用户关掉电池优化。
2. **省电会吞广播**。安卓息屏后限制 WiFi 广播/组播，就算进程活着，发现心跳也可能发不出去。
3. **它并不能解决"异地"**。手机当房主时，手机多半在移动流量或校园网里 ——
   **就是你已经踩过的那个坑**：私网地址外面到不了。
   该穿透还得穿透，而穿透客户端只有 PC/服务器版，**手机端跑不了**。
   所以"手机组局"只在**大家同一个 WiFi / 同一个手机热点**下成立。

### 建议

- **现在不做**：收益只有一个场景（几个人手边没有电脑，比如宿舍 / 车上），
  代价是异步桥改造 + 前台服务 + 房间会随房主息屏消失 + APK 变大 + 我这边没有安卓设备只能靠你测。
- **如果真要做**，按**最小可用版**单开一轮：只支持 2–6 人同 WiFi，
  不做落盘恢复 / 观战 / 房间码，界面明说「请保持屏幕常亮」。
  这样能把异步桥的复杂度压住，也便于真机验收。
