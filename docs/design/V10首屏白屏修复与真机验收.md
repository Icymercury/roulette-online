# 生死转盘 · V10 交付：首屏白屏修复 + 真机验收闸门

> 日期：2026-09-24
> 触发：赐红反馈「手机端 APK 看不到填 IP 的地方，电脑端也一样」

---

## 一、你看到的现象

手机 APK 打开后只有一块「房 间 大 厅 / 等待进入房间…」的弹窗，
**没有任何输入框、看不到「进入房间」按钮**。电脑端一模一样。

---

## 二、根因：一个写错的变量名，整页从诞生第一天就是死的

`client.html` 的 `buildWheel()` 里（原第 746 行）：

```js
const t  = pt(cx, cy, r * 0.60, mid);              // t  = 坐标数组 [x, y]
const tx = document.createElementNS(NS, 'text');    // tx = 真正要插入的文字节点
...
wheel.appendChild(t);        // ← 插进去的是个数组
```

真浏览器直接抛：

```
TypeError: Failed to execute 'appendChild' on 'Node':
           parameter 1 is not of type 'Node'
```

而这个位置是 `init()` 的**第一行**。于是：

```
init() 第一行 buildWheel() 抛异常
  └→ init() 中断，后面的 render() 从来没执行过
      └→ #lobbyOverlay 在 HTML 里写死了 class="overlay show"，
         本该由 render() 关掉，现在没人关
          └→ 遮罩是全屏的（position:fixed; inset:0; z-index:60）
              └→ 「填服务器地址」那一栏被永久盖住
```

一句话：**联机客户端从来没有在真浏览器里跑起来过。**
你以前玩的是单机页 `roulette-wheel.html` —— 那一份的变量名是反的（那里 `t` 才是文字节点），所以它一直好好的；`client.html` 是从它改写过来的，改写时换掉了变量名，`appendChild` 忘了跟着换。

> 顺带解释「电脑端也一样」：PC 的 exe 和手机的 APK 内置的是**同一份** `client.html`，所以两端是同一个死法。

---

## 三、为什么 452 条断言全绿，却没人发现

五套 Node 测试都在「假 DOM」里跑，而假 DOM 之前的实现是：

```js
appendChild(c) { el.children.push(c); return c; }   // 给啥收啥
```

真 DOM 会校验类型，假 DOM 不会。**测试环境比生产环境宽容，等于没测。**

这不是一次偶发失误，是一类系统性风险 —— 凡是「假 DOM / 假接口」的测试都自带这个盲点。所以这轮的修法不是只改一行代码，而是补上一道只在**真 Chromium** 里才成立的闸门。

## 五、新防线：三层，各挡一类错

| 层 | 脚本 | 挡的是什么 |
|---|---|---|
| ① 假 DOM（Node） | 五套测试，466 条 | 规则、协议、界面状态 |
| ② **真渲染** | `build/verify-page.js`，9 条 | 「页面在真浏览器里根本画不出来」（V10 事故就死在这一层） |
| ③ **真连通** | `build/verify-live.js`，13 条 | 「页面画得出来但连不上、开不了局」 |

**② 真机验收（`build/verify-page.js`）** 在真 Chromium 里跑，最关键两条：

- **★ 服务器地址输入框点得到（没被遮挡）**
  做法：用 `document.elementFromPoint()` 打在地址框正中心，看命中的元素是不是它自己。
  **这一条就是你这次遇到的问题本身** —— 以后不用靠肉眼发现。
- 转盘画出了 5 个扇形 + 5 条事件文字 + 中心「命运」。

**③ 真·端到端（`build/verify-live.js`）** 不走假 DOM、也不只截图：
起真服务端 → 无头浏览器（手机尺寸 390×844）打开页面 → **像真人一样填名字、点「进入房间」、
再点「开始赌局」**，然后检查：连上了吗？进大厅了吗？自己是房主吗？开局了吗？用 CDP 直接驱动。

两层都会连 `console.error` 一起抓 —— 因为页面里有 try/catch 兜底，光靠 `window.onerror`
会漏掉被兜住的错误（这轮就吃过一次：兜底之后「没有未捕获异常」通过了，但转盘还是只有 1 块扇形）。

**②③ 都焊进了打包流程**（页面是死的就根本打不出包），另外打包后还会把
exe / APK 里**那份**页面抽回来再过一遍 ②：

```
改 client.html
  → node build/verify-page.js      ← 渲染层，打包前自动跑
  → node build/verify-live.js      ← 连通层，改联机代码后手动跑（默认不在打包闸里，避免拖慢）
  → node build/build-pc.js         ← 自动跑 ②，打完再把 exe 里那份页面抽出来跑 ②
  → node build/build-android.js    ← 同上，抽 APK 里的页面
```

## 六、怎么办：两个产物（都在 `D:\Trae打包文件\生死转盘\`）

| 文件 | 说明 |
|---|---|
| `生死转盘-服务端.exe` | 83 MB，Node SEA 单文件。双击起服，**朋友不用装 Node** |
| `生死转盘-手机版.apk` | 101 KB，安卓壳，minSdk 21（安卓 5.0+ 都能装） |

**上手三步：**

1. 电脑双击 `生死转盘-服务端.exe`（防火墙弹窗点「允许」）
2. 黑窗口里找到这一行，抄下地址（形如 `http://192.168.1.5:8080`）
   ```
   别人用这些地址连（手机 / 电脑 / 平板都行，同一个地址就是同一个房间）：
                   http://192.168.1.5:8080    ← 以太网
   ```
3. 手机装 APK → 打开 → 把地址填进最上面那一栏 → 填名字 → 点「进入房间」

> **互联的答案：能，而且是天生就能。**
> 手机和电脑连的是**同一个 `server.js`**、走**同一套 WebSocket 协议**、用**同一个 `engine.js`**。
> 没有两套实现要对齐 —— 连同一个地址就进同一个房间，数字天然一致。
> 手机端不需要单独的服务端，PC 端也不需要单独的协议。

**升级安装**：这版起签名固定（密钥存在 `build/debug.keystore`），以后直接覆盖安装即可。
⚠️ 但**这次**要先卸载旧 APK 再装 —— 之前几次打包用的签名各不相同。

## 八、还没做的 / 风险（不遮掩）

1. **APK 仍然没在真安卓机上装过。** 本机没有模拟器也没有系统镜像。
   这轮做到的是：结构验收（签名 / 包名 / 入口 / minSdk / 资源齐全）
   + **APK 内置页面在真 Chromium 里的渲染验收** + **真浏览器点进房间并开局的连通验收**
   + 签名指纹稳定性实测。这比上次多三层保障，但**仍然不等于在真安卓上跑过** ——
   **首次上机请你自己装一遍试**（`adb logcat -s Roulette` 能看到页面 console，壳里已经接好了）。
2. **局域网 http 下 PWA 仍是残的。** Service Worker 只在安全上下文能注册，`http://192.168.x.x` 不算。所以浏览器方式只是「主屏幕快捷方式」，装 APK 才是完全体。想要 PWA 也完整，得给服务端加自签 HTTPS（手机会弹证书警告）—— 你定。
3. **老账没还**：第 71 转的死神镰刀形同虚设（能活到 71 转的玩家 96% 会通关），瓶颈是金币存量而不是每转伤害。等你定夺。
4. 单服务器仍然只有**一个房间**：两群朋友同时玩，得各起一个端口（`生死转盘-服务端.exe 8081`）。
