### 为什么删「减少转数」（这条值得写下来）

对赌轮盘的轮盘是**全场共享**的，镰刀档位挂的是**全局转数**。
「减少转数」在这套结构下不是"给自己买时间"，而是**"把所有人一起往后拖"**：

- 它压的是全局读数 `k` → 镰刀档位跟着往回退 → 全场一起少挨刀。
- 于是它变成一件**"个人付费、全员受益"**的道具，谁买谁亏（相对其他玩家）。
- 更糟的是它会**和死神利息串成闭环**：利息 + 减少转数 = 用资源无限买时间，赌局可以永不收场
  （这条在 V6 就实测过，是当时 48% 僵局的元凶之一）。

**删掉之后僵局风险反而下降**（见第四节）：没人能再拖后腿，共享镰刀只会一路往前推。

> 减少转数**仍然存在于单机「死亡轮盘」**，那里轮盘是自己的、回收 5 转就是纯赚。这条没动。

### 2.2 掉线封存（三层实现）

**引擎层（纯函数，可单测）**

| 函数 | 作用 |
|---|---|
| `pauseMatch(m, now)` | 把对局标记为封存，记下 `frozenSince`。幂等（已封存再调不变） |
| `resumeMatch(m, now)` | 解封，把这次封存的时长累加进 `pausedMs`。幂等 |
| `elapsedMs(m, now)` | 对局已进行的**有效时长** = `now − startedAt − pausedMs − (正在封存的那段)` |

- 封存期间 `applyAction` **拒绝一切动作**，返回 `rejected.reason = 'frozen'`。
- 封存**不改任何数值**（血量 / 金币 / 读数 / 转数全冻结）。
- **封存等待的时间不计入任何人的存活时间** —— 死神追猎是按用时排名的，
  掉线等人的 10 分钟绝不能算进成绩。这条由 `elapsedMs` 保证，死亡打点用的是它。

**服务端层（自动）**

- 任何人掉线 → `syncFreeze()` 立刻把对局封存，广播 `freeze` 事件（点名是谁掉线）。
- 全员回到在线 → 自动解封，广播 `thaw` 事件（带上刚封存了多少秒）。
- **掉线的人那一回合不会被跳过**：对局停着等他，因为这是朋友局，等得起。
- 大厅里有人掉线 → **不许开局**（`rejected.reason = 'player-offline'`，附带名单）。
- 房主随时可以「放弃本局」把对局收回大厅（这是唯一的逃生出口）。

**客户端层（见到的样子）**

- 封存中：顶部出现封存提示条 —— 谁掉线、已封存多久、**说明暂停计时与结算**。
- 转动按钮变成「已 封 存」并禁用；商场所有按钮禁用；掉线的人卡片上打「掉线」标记。
- 房主额外看到「放弃本局」按钮。
- 掉线的人重新打开页面：连接状态显示「**正在恢复你的角色…**」→ 成功后横幅「已恢复你的角色」。

### 2.3 重连凭证（为什么知道编号也顶不了号）

- 每个座位在入座时分配一枚 **16 字节随机 token（32 位十六进制）**，存在浏览器 `localStorage`。
- **token 是恢复座位的唯一凭据**：光知道编号（`id`）恢复不了，服务端回 `bad-token`。
- token 只发给本人（`welcome` 消息里），**绝不出现在广播视图里**（有断言守着）。
- 拿旧 token 进来 → 回到原编号、原血量、原金币、原道具，**不会被当成新人重开一个座位**。

### 2.4 落盘与重启恢复

- 对局状态实时写 `state.json`（临时文件 + rename 原子写）。
- 服务重启后自动恢复：座位、模式、血量、金币、道具、转数全回来。
- **重启后若对局进行中且无人回来，自动进入封存状态**（避免开着表空转）。
- 超过 **12 小时**的旧存档不再自动恢复。
- 测试可用环境变量 `RR_STATE` 指到别处，避免覆盖真实存档。

### 2.5 安全加固（本轮新增四项）

| 措施 | 作用 |
|---|---|
| **静态服务白名单** | 只发 `client.html` / `roulette-wheel.html` / `online-test.html` / `engine.js` + 静态资源后缀。`server.js`、`state.json`、`.workbuddy/`、测试脚本**一律 404** |
| **重连 token** | 知道编号也顶不了别人的座位 |
| **消息频率限制** | 单连接每秒超过 60 条消息 → 断开 |
| **连接看门狗** | 45 秒没收到任何帧 → 当掉线处理（防止半死连接把对局吊住） |

## 五、这轮修掉的两个真坑

### 5.1 【真 bug】断线从来没被检测到过

**症状**：v2 里掉线的人永远显示"在线"，对局卡着不动，重连也接不回来。

**根因**：`http.Server` 的 `upgrade` 事件给出来的 socket 是**半开（allowHalfOpen）**的。
对端关闭时它只触发 `'end'`，**永远不触发 `'close'`**。
v2 只在 `socket.on('close')` 上挂了掉线处理 —— 于是那段代码从来没执行过。

**修法**：`'end'` / `'close'` / `'error'` 三个都挂上 `drop(client)`。

> 教训：**写透一个"回调没被调用"的 bug，唯一办法是往里塞临时日志看它到底有没有跑。**
> 当时我先怀疑协议、怀疑客户端，最后靠几行 dbg 才定位到"事件压根不触发"。

### 5.2 【测试自身的错】两条断言押注在了随机结果上

- `test-online.js`：关掉最后一条连接会让对局**封存**，下一节紧接着发转动 → 有概率被 `frozen` 拒。
  （修：连回来解封再继续。）
- `client-mp-test.js`：断言"踩香蕉皮后血或金**必有变化**"。
  但**满血时掷出「加血」数值本来就不该变** —— 这是机制正确，不是没结算。
  （修：改成断言"转盘确实转过了（角度变了）"，数值层面交给引擎测试用固定随机流精确验证。）

> 教训：**断言不要押注在随机结果上。**要断言"某个不变量"（转数没涨 / 角度变了），
> 而不是"某个随机分支恰好发生了"。改完连跑 4 次全绿才算稳定。

## 六、答疑：还是内网穿透吗？IP 会不会被陌生人访问？

**直接回答：现在不是内网穿透，默认也不会把服务开给公网。**

`server.js` 里写的是 `server.listen(PORT, '0.0.0.0')`。这行的意思是
**"绑定本机所有网络接口"**，而不是"开放到互联网"。具体说：

| 谁 | 能不能连上 | 说明 |
|---|---|---|
| 本机浏览器（`localhost:8080`） | ✅ | 回环，随便连 |
| **同一局域网**（同一个 WiFi / 路由器下） | ✅ | 这是 `0.0.0.0` 的实际效果 |
| **同一个虚拟内网**（Tailscale / ZeroTier 等给你的 `100.x.x.x`） | ✅ | 你主动把设备拉进同一个私有网才有 |
| **公网上的陌生人** | ❌ **默认连不上** | 你的机器在内网，公网根本没有通向它的路 |

**陌生人唯一能连上的前提，是你自己主动打通了一条公网路径** ——
比如 Tailscale Funnel、cloudflared 隧道、路由器端口转发、或者买台云服务器。
不做这些，别人连你的地址都解析不到，更别说"扫到端口"。

> 换句话说：**"暴露 IP"的风险不来自这个游戏，来自你选的穿透方式。**
> 游戏代码本身一行都没有往公网开洞。

### 万一你真开了公网路径，这轮的加固是这样的

| 层级 | 挡什么 |
|---|---|
| **房间码**（`node server.js 8080 你的口令`） | **唯一真正的准入闸门**。没口令 → `bad-room-code`，连门都进不去 |
| 静态白名单 | 就算进了门，也拿不到 `server.js` 源码和 `state.json` 存档（**存档里有 token**，泄露等于送号） |
| 重连 token | 就算知道别人编号，也顶不了他的座位 |
| 频率限制 + 45 秒看门狗 | 挡刷消息、挡半死连接吊住对局 |

### 给你的一句话结论

> **安全模型 = 朋友局 + 房间码 + 需要时再开穿透、玩完就关。**
>
> - 平时：局域网 / Tailscale 内网直连，公网完全看不到你。
> - 想让朋友零安装从外网进来：用 **Tailscale Funnel + 房间码**（地址固定、免备案、免费）。
>   **切记：开 Funnel 时一定带房间码** —— Funnel 是公网可达的，不带口令就是真的裸奔。
> - **没带房间码**起服务器 = 任何能找到这个地址的人都能加入。只要你不主动打通公网路径，
>   "能找到地址的人"就只有你同网段的朋友。

## 七、已知限制 / 待办

1. **掉线不跳过、无限等**：这是本轮按你的选择做的（朋友局，等得起）。
   如果实际玩起来遇到"某个人一直不回来"，房主的出口是**放弃本局**回大厅重开。
   要不要加个"封存超过 N 分钟提示房主"的软提示，等你玩过再说。
2. **房间码还没测**：服务端已支持（口令错误 → `bad-room-code`），客户端有输入框，
   但"口令错误 / 中途换码"这两条路径没有断言覆盖。
3. **打包 exe**（Bun compile / Node SEA）：只对你有价值（免装 Node），朋友侧零收益。
   详见 `exe与Tailscale集成研判.md`。
4. **Tailscale Funnel**：朋友零安装方案，地址固定、免备案。配合房间码使用。
