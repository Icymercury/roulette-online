# V9 · 房主迁移 / 退出本局转观战 / 双端打包

> 日期：2026-09-24
> 本轮需求（赐红原话）：
> 「房主自动迁移功能加上，然后给其他玩家退出本局功能加上，同时，退出本局不退出房间，转入观战模式，然后给观战模式加退出观战的功能，再做一个不在本局游戏的玩家进入房间后可以选择观战，最后，做两版。手机apk版本和pc端版本，你看看对于手机端和pc端能不能互联」

---

## 一、先回答"能不能互联"

**能，而且是结构上就通，不是"我们想办法让它通"。**

| | 用什么跑 | 连到哪 |
|---|---|---|
| PC 端 | `生死转盘-服务端.exe`（内置 Node 运行时，双击即起服） | 它就是服务器 |
| 手机端 | `生死转盘-手机版.apk`（安卓壳）或手机浏览器 | `ws://<电脑局域网IP>:8080` |

两端的**服务端只有一个**（就是 PC 上那个 exe），**协议只有一套**（原生 WebSocket 传 JSON 帧），**规则只有一份**（`engine.js`）。
所以不存在"两套实现要对齐"的问题 —— 手机连上电脑，就进了同一个房间、同一张转盘。

这跟"两个客户端各跑各的再同步"是完全不同的架构：**没有客户端权威**，所有掷骰、结算、扣血扣金都在服务端完成，客户端只负责发指令 + 重播事件。
手机和电脑看到的数字天然一致。

## 二、本轮功能改动

### 1. 房主自动迁移

- `ensureHost()`：当前房主不在线时，把房主转给**编号最小的在线成员**（先看选手，再看观战）。
- 触发时机：`drop()`（掉线）和 `quit()`（观战退出房间）。
- **原房主回来不自动回任** —— 否则 A 掉一下、B 掉一下，房主身份来回横跳，每次都要重新同步。
  迁移是单向的：谁被迁走了就不再收回。

### 2. 退出本局（转观战，不离房）

- 引擎新增 `leaveMatch(match, playerId, now) → {match, events, seat}`（`engine.js` v3.2）。
- 关键细节：
  - **不推进回合指针**。删人后如果下标大于 `turn` 就减 1，保证"轮到走的人走了"不会白白送给下一个人一个回合。
  - **不碰房内席位**。函数把座位 `{id,name,token,connected}` 原样交回给服务端，服务端据此把人转成 watcher（同 id、同 token）。
  - **立即重判结束**：剩 2 人时对方直接胜（`last-standing`）；走光了则 `all-left`。
  - **冻结中也能走**。这条很重要 —— 房主掉线会封存对局，如果这时候不许别人退出，其他人就被锁死在一个打不动的房间里了。
  - 纯函数：不改入参，返回新对象。

### 3. 退出观战（真的离房）

- 观战角标 → `退出观战` 按钮 → 发 `quit` → 服务端删掉 watcher、广播 `left-room` → 客户端回到连接条。
- 观战退出后**不再保留任何席位**，重进要靠重新 join。

### 4. 对局中进房 → 可选观战

原来对局进行中进来会被 `game-in-progress` 硬拒。现在拒绝消息带上了 `canSpectate` / `modeLabel` / `players`，
客户端据此弹「本局进行中 · 想旁观还是等下一局？」的浮层，选观战就以 watcher 身份进房。

### 5. 观战模型（服务端）

房间成员分两类：

- **选手**：有座位（`id/name/token/connected`），能操作。
- **观战者**：`room.watchers[]`，**沿用同一个 id 与 token**。

沿用同一枚 token 是故意的 —— 房主身份、断线重连、回大厅时"观战者自动回到选手名单"这三件事全都不用写特例。

## 五、手机端的几个硬约束（踩过的坑，记下来别重复踩）

### 1. 安卓 9+ 默认禁明文流量

局域网联机就是 `http://` / `ws://`，属于明文。清单里必须写
`android:usesCleartextTraffic="true"`，否则 WebView 连不上，报的是很难懂的错。

### 2. 局域网 http 下浏览器会禁用 Service Worker

SW 只在**安全上下文**（https 或 localhost）里能注册。手机连的是 `http://192.168.x.x`，属于非安全上下文，浏览器直接拒绝。
所以：

- 手机端的 PWA **不等于**完全体 App，只是"主屏幕快捷方式"，可能有地址栏。
- **游戏本体完全不依赖 SW**。SW 只做离线缓存。客户端里已经加了探测，注册不了就静默跳过，不再往控制台喷错。

### 3. APK 里的页面必须用相对路径

网页方式 `client.html` 由服务器发，绝对路径 `/engine.js` 没问题；
但安卓壳是用 `file:///android_asset/www/client.html` 加载的，`/engine.js` 会解析成 `file:///engine.js` → 404。

所以本轮把 `engine.js` / `manifest.json` / 图标全改成了**相对路径**。
`client-mp-test.js` 里加了钉子（`!<script src="/`），防止以后被改回绝对路径。

### 4. `file://` 下 localStorage 不可靠 → 走原生存储

座位凭证丢了就回不到自己的座位。壳里注册了 `window.RRNative` 桥，把 Key-Value 写进
SharedPreferences；客户端的 `SS` 优先用桥，桥不在才退回 localStorage。

### 5. 本机 d8 遇到匿名内部类必崩（构建期约束）

build-tools 34 自带的 d8（R8 8.2.2-dev）读到匿名内部类的 class 文件会崩：

```
java.lang.NullPointerException: Cannot invoke "String.length()" because "<parameter1>" is null
```

实测：顶层类 OK，匿名内部类 FAIL（对照实验见 `android/java/.../MainActivity.java` 顶部注释）。

**所以壳代码里一个嵌套类、匿名类、lambda 都不许有** —— 回调类全部写成同文件的顶层
package-private 类。`MainActivity.java` 开头写了醒目警告，别再改回去。

## 六、打包链路（不用 gradle）

本机 gradle 官方源连不上，所以没走 AGP，用裸工具链自己串：

```
aapt2 compile   res/ → 二进制资源
aapt2 link      清单 + 资源 + assets → 未签名 APK（含 R.java）
javac           编译壳代码（对着 android.jar，-source 8 -target 8）
d8              字节码 → classes.dex
python zipfile  把 classes.dex 塞进 APK
zipalign -p 4   对齐
apksigner       签名（自动生成 debug keystore）
```

工具链位置（都在 D 盘，没碰 C 盘）：

- `D:\Android\android-sdk\platforms\android-34\android.jar`
- `D:\Android\android-sdk\build-tools\34.0.0\`（由 `build/fetch-android-tools.js` 从 dl.google.com 装的，56 MB）
- `D:\Java21\java21`

构建脚本：

- `build/build-android.js` → 打 APK
- `build/build-pc.js` → 打 exe
- `build/fetch-android-tools.js` → 新机器上一键装 build-tools
- `build/inject-dex.py` → 把 dex 合进 APK（本机没有 `zip` 命令，用 Python 标准库）
- `build/make-icons.js` → 生成图标 PNG（手写 PNG 编码器，零依赖）

**一个坑**：aapt2 打不开中文路径（直接报"找不到目录"）。
所以两个构建脚本都会把工程先复制到纯 ASCII 工作目录（`D:/Android/rrbuild`）再编译，
最终产物才拷回中文目录。

## 七、已知限制

1. **APK 没在真机/模拟器上跑过。** 本机没装 emulator 和系统镜像，所以只做到了"结构验收"：
   签名通过、清单正确（包名/入口/minSdk）、8 个内置页面都在。**首次上机请先自己装一遍试。**
2. **APK 是 debug 自签名的。** 侧载安装没问题；要上应用商店得换正式 keystore。
3. **服务端只对同网段开放。** 监听 `0.0.0.0`，局域网 / Tailscale 能连，不是开给整个互联网 ——
   但同网段的人确实能连上，建议带上房间码。
4. **手机端 PWA 在明文 http 下拿不到完全体体验**（见五.2）。要真·完全体就装 APK，或给服务端上自签 HTTPS。
